بوابة دفع صُرّة للتجار

اقبل مدفوعات USDT في متجرك أو تطبيقك. المبلغ يصل مباشرة إلى محفظتك، ونحن نؤكد لك الدفع تلقائياً.

كيف تعمل؟

  1. نظامك يطلب من الـ API فاتورة بمبلغ معيّن، فيرجع له رابط صفحة دفع.
  2. العميل يفتح الرابط ويرسل USDT مباشرة إلى محفظتك من أي محفظة أو منصة.
  3. نراقب الشبكة، وعند وصول التحويل نرسل إلى خادمك إشعاراً موقّعاً بأن الفاتورة دُفعت.
غير احتجازية: أموال عملائك لا تمر بنا أبداً، فلا نستطيع حجزها أو تأخيرها. دورنا التأكيد والإشعار فقط.

كيف نعرف أن التحويل يخص فاتورتك؟

نضيف إلى المبلغ كسراً صغيراً فريداً أقل من سنت واحد. فاتورة بـ 10 USDT يدفعها العميل 10.004321 مثلاً. لذلك يجب أن يرسل العميل المبلغ المعروض بالضبط.

البدء في 3 خطوات

  1. ثبّت تطبيق صُرّة، وافتح القائمة ← بوابة الدفع للتجار، واكتب اسم متجرك. عنوان الاستلام هو محفظتك في صُرّة.
  2. اضغط إنشاء مفتاح API وانسخه. يظهر مرة واحدة فقط، فاحفظه في خادمك ولا تضعه في كود الواجهة أو التطبيق.
  3. أنشئ أول فاتورة بالطلب التالي.
curl -X POST https://osdojhpsfbcqguoctbpk.supabase.co/functions/v1/pay/v1/invoices \
  -H "Authorization: Bearer sk_live_XXXXXXXX" \
  -H "Content-Type: application/json" \
  -d '{"amount":"10","network":"bsc","order_id":"ORDER-1001","description":"طلب رقم 1001"}'

الرسوم

حسابك فيه رصيد مدفوع مسبقاً بـ USDT. عن كل فاتورة مدفوعة نخصم 0.5% من مبلغها، بحد أدنى 0.02 USDT. الفواتير غير المدفوعة مجانية. يبدأ كل حساب برصيد تجريبي 1 USDT، وتشحن الرصيد من نفس الشاشة في التطبيق. إذا لم يكفِ الرصيد لعمولة فاتورة جديدة، يرجع الخطأ INSUFFICIENT_CREDIT.

مرجع الـ API

إنشاء فاتورة.

الحقلالوصف
amountإلزامي. نص مثل "25" أو "25.50". من 1 إلى 100000، وبخانتين عشريتين كحد أقصى.
networkإلزامي: bsc أو tron أو polygon أو eth. ننصح بـ bsc لأن رسومها على العميل سنتات.
order_idاختياري، وننصح به: رقم الطلب عندك (حتى 64 حرفاً: حروف لاتينية وأرقام و. : - _). إعادة الطلب بنفس الرقم ترجع الفاتورة نفسها ولا تنشئ ثانية.

إشعار الدفع (Webhook)

أضف رابط خادمك (https فقط) في شاشة بوابة الدفع في التطبيق. عند دفع أي فاتورة نرسل إليه طلب POST:

{
  "event": "invoice.paid",
  "invoice": { "id": "inv_…", "status": "paid", "order_id": "ORDER-1001",
               "amount": "10", "pay_amount": "10.004321", "network": "bsc",
               "tx": "0x…", "paid_at": "2026-11-12T14:07:31Z" }
}

تحقّق من التوقيع دائماً

أي شخص يعرف رابطك يستطيع أن يرسل له طلباً مزيّفاً. كل إشعار منا يحمل الترويسة X-Sarra-Signature: t=<وقت>,v1=<توقيع>، والتوقيع هو HMAC-SHA256(سر_الإشعار, t + "." + نص_الطلب_الخام). سر الإشعار (whsec_…) تجده في نفس الشاشة.

// Node.js (Express): استخدم النص الخام للطلب، لا الكائن بعد تحليله
const crypto = require('crypto');
app.post('/sarra-hook', express.raw({ type: 'application/json' }), (req, res) => {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/.exec(req.get('X-Sarra-Signature') || '');
  if (!m || Math.abs(Date.now() / 1000 - Number(m[1])) > 300) return res.sendStatus(400);
  const expected = crypto.createHmac('sha256', process.env.SARRA_WEBHOOK_SECRET)
    .update(m[1] + '.' + req.body).digest('hex');
  if (!crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(m[2]))) return res.sendStatus(400);
  const { event, invoice } = JSON.parse(req.body);
  if (event === 'invoice.paid') markOrderPaid(invoice.order_id, invoice.id); // اجعلها آمنة للتكرار
  res.sendStatus(200);
});
<?php // PHP
$raw = file_get_contents('php://input');
preg_match('/^t=(\d+),v1=([0-9a-f]{64})$/', $_SERVER['HTTP_X_SARRA_SIGNATURE'] ?? '', $m) or exit(http_response_code(400));
if (abs(time() - (int)$m[1]) > 300) exit(http_response_code(400));
$expected = hash_hmac('sha256', $m[1] . '.' . $raw, getenv('SARRA_WEBHOOK_SECRET'));
if (!hash_equals($expected, $m[2])) exit(http_response_code(400));
$data = json_decode($raw, true);
if ($data['event'] === 'invoice.paid') mark_order_paid($data['invoice']['order_id'], $data['invoice']['id']);
http_response_code(200);
  • ردّ بكود 2xx خلال 8 ثوانٍ. إن لم يصل الرد نعيد المحاولة 6 مرات على مدى نحو 16 ساعة.
  • قد يصلك الإشعار نفسه أكثر من مرة، فلا تسلّم الطلب مرتين: تحقق من invoice.id.
  • بدون رابط إشعار، استعلم عن الفاتورة بـ GET /v1/invoices/{id} كل بضع ثوانٍ.

الأخطاء

الخطأ يرجع بالشكل {"error":"CODE"}:

الرمزHTTPالمعنى
UNAUTHORIZED401المفتاح ناقص أو خاطئ أو استُبدل بمفتاح جديد.
INSUFFICIENT_CREDIT402الرصيد لا يكفي لعمولة هذه الفاتورة. اشحن الرصيد من التطبيق.
BAD_AMOUNT400صيغة المبلغ غير صحيحة. ومعها AMOUNT_TOO_SMALL وAMOUNT_TOO_LARGE.
BAD_NETWORK400شبكة غير مدعومة.
NETWORK_NOT_CONFIGURED400لا يوجد عنوان استلام لهذه الشبكة في حسابك.
BAD_ORDER_ID400order_id فيه رموز غير مسموحة أو أطول من 64.
TOO_MANY_PENDING400عندك 200 فاتورة معلّقة. انتظر انتهاء بعضها.
RATE_LIMITED429طلبات كثيرة. الحد 300 فاتورة في الساعة.
NOT_FOUND404الفاتورة غير موجودة في حسابك.

ملاحظات مهمة

  • التأكيد يأخذ من دقيقة إلى ثلاث دقائق بعد وصول التحويل، لأننا ننتظر تثبيته على الشبكة.
  • المبلغ المختلف لا يُحتسب تلقائياً. لو أرسل العميل مبلغاً ناقصاً أو زائداً فقد وصل إلى محفظتك فعلاً، لكن الفاتورة تبقى غير مدفوعة، وتسوّيه أنت مع عميلك.
  • الدفع بعد انتهاء المهلة يُقبل خلال 20 دقيقة إضافية، ثم تُغلق الفاتورة نهائياً.
  • الاسترجاع: المبلغ في محفظتك، فأنت من يعيده للعميل إن لزم.
  • أمان المفتاح: إن تسرّب، أنشئ مفتاحاً جديداً من التطبيق، فيتوقف القديم فوراً.
  • تتحمل أنت الالتزام بقوانين بلدك في بيع السلع والخدمات وقبول العملات الرقمية.
