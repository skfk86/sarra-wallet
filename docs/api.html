اقبل USDT في متجرك

طلب واحد ينشئ فاتورة. العميل يدفع إلى محفظتك مباشرة، وخادمك يعرف فوراً أن الدفع تم.

ما هذه؟ابدأجرّب الآنمثال كاملإشعار الدفعالمرجعالأخطاءالرسوم

ما هذه البوابة؟ (شرح بدون مصطلحات)

تخيّل أن عندك متجراً على الإنترنت، وتريد أن يدفع لك الزبون بالـ USDT. المشكلة: كيف يعرف متجرك أن هذا الزبون بالذات دفع، وكم دفع، ومتى؟

البوابة تحل هذا. متجرك يطلب منها "فاتورة" بمبلغ معيّن، فتعطيه رابط صفحة دفع. الزبون يدفع من أي محفظة، والمال يذهب إلى محفظتك أنت مباشرة. البوابة تراقب الشبكة، وحين يصل التحويل تخبر متجرك: "الطلب رقم كذا دُفع".

مثال: متجر أحمد

1زبون يضغط "اشترِ" على كتاب بـ 5 دولار في موقع أحمد.
2موقع أحمد يطلب من صُرّة فاتورة بـ 5 USDT، فيحصل على رابط صفحة دفع.
3الزبون يفتح الصفحة، يرى المبلغ والعنوان ورمز QR، ويدفع.
4الـ 5 USDT تصل محفظة أحمد مباشرة.
5صُرّة تخبر موقع أحمد أن الدفع تم، فيرسل الكتاب للزبون تلقائياً.

الكلمات التي ستقابلها

APIطريقة يتكلم بها برنامجك مع صُرّة: يرسل طلباً ويستقبل رداً.
مفتاح APIكلمة سر طويلة تبدأ بـ sk_live_، تثبت أن الطلب منك. تحصل عليها من التطبيق.
فاتورةطلب دفع واحد: مبلغ، شبكة، ومهلة 30 دقيقة.
Webhook (إشعار الدفع)رسالة ترسلها صُرّة إلى خادمك تلقائياً لحظة الدفع، بدل أن تسأل أنت كل مرة.
الرصيدرصيد صغير مدفوع مسبقاً تُخصم منه عمولة الخدمة. ليس مال زبائنك.

ما الـ 1 USDT الذي يبدأ به حسابك؟

هو رصيد عمولات مجاني للتجربة، وليس مالاً يُرسل لك ولا يُسحب. عن كل فاتورة يدفعها زبون نخصم عمولتنا من هذا الرصيد (0.5%، وأقلها 0.02 USDT)، بينما يصلك مبلغ الزبون كاملاً في محفظتك.

مثال: زبون دفع 10 USDT ← يصل محفظتك 10 USDT كاملة، وينقص رصيد العمولات 0.05. الـ 1 USDT يكفي لنحو 50 فاتورة صغيرة. حين ينتهي تشحنه من شاشة بوابة الدفع في التطبيق.

هل أحتاج أن أكون مبرمجاً؟

لربط موقعك تلقائياً، نعم: تحتاج من يضيف طلبين بسيطين في خادم موقعك (الأمثلة أدناه جاهزة للنسخ). أما للتجربة فقط فلا: جرّب من المتصفح بدون كتابة أي كود.

تحقّق من التوقيع

أي شخص يعرف رابطك يستطيع إرسال إشعار مزيّف، لذلك كل إشعار منا موقّع بسر الإشعار (whsec_…) الذي تجده في نفس الشاشة. انسخ الدالة الجاهزة:

const crypto = require('crypto');

// ترجع true إذا كان الإشعار من صُرّة فعلاً
function isFromSarra(signatureHeader, rawBody, secret) {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/.exec(signatureHeader || '');
  if (!m) return false;
  if (Math.abs(Date.now() / 1000 - Number(m[1])) > 300) return false; // أقدم من 5 دقائق
  const expected = crypto.createHmac('sha256', secret)
    .update(m[1] + '.' + rawBody).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(m[2]));
}

// مثال مع Express: خذ النص الخام للطلب، لا الكائن بعد تحليله
app.post('/sarra-hook', express.raw({ type: 'application/json' }), (req, res) => {
  const raw = req.body.toString();
  const ok = isFromSarra(req.get('X-Sarra-Signature'), raw, process.env.SARRA_WEBHOOK_SECRET);

  const { event, invoice } = JSON.parse(raw);
  if (event === 'invoice.paid') markOrderPaid(invoice.order_id, invoice.id);

function is_from_sarra(string $signatureHeader, string $rawBody, string $secret): bool {
  if (!preg_match('/^t=(\d+),v1=([0-9a-f]{64})$/', $signatureHeader, $m)) return false;

from flask import Flask, request

app = Flask(__name__)

# ترجع True إذا كان الإشعار من صُرّة فعلاً
def is_from_sarra(signature_header, raw_body, secret):
    m = re.fullmatch(r't=(\d+),v1=([0-9a-f]{64})', signature_header or '')
    if not m:
        return False
    if abs(time.time() - int(m[1])) > 300:  # أقدم من 5 دقائق

    msg = m[1].encode() + b'.' + raw_body
    expected = hmac.new(secret.encode(), msg, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, m[2])

@app.post('/sarra-hook')

ثلاث قواعد:
  • ردّ بكود 200 خلال 8 ثوانٍ. إن لم يصل ردّك نعيد المحاولة 6 مرات على مدى نحو 16 ساعة.
  • قد يصلك الإشعار نفسه أكثر من مرة. لا تسلّم الطلب مرتين: تحقق من invoice.id.
  • استخدم نص الطلب الخام في التحقق، لا الكائن بعد تحليله.

للمهتمين بالتفاصيل: الترويسة X-Sarra-Signature: t=<وقت>,v1=<توقيع>، والتوقيع هو HMAC-SHA256(السر, t + "." + نص_الطلب).

الرسوم

حسابك فيه رصيد مدفوع مسبقاً بـ USDT. عن كل فاتورة مدفوعة نخصم 0.5% من مبلغها، بحد أدنى 0.02 USDT. الفواتير غير المدفوعة مجانية.

يبدأ كل حساب برصيد عمولات مجاني 1 USDT (يكفي لنحو 50 فاتورة صغيرة)، وهو ليس مالاً يُسحب. تشحن الرصيد من شاشة بوابة الدفع في التطبيق.

أسئلة شائعة

لماذا pay_amount يختلف قليلاً عن amount؟

نضيف كسراً صغيراً فريداً أقل من سنت واحد لنعرف أن التحويل يخص فاتورتك. فاتورة بـ 10 يدفعها العميل 10.004321 مثلاً، ويجب أن يرسل هذا الرقم بالضبط.

هل تمر أموال عملائي بكم؟

لا. التحويل يذهب من العميل إلى محفظتك مباشرة، فلا نستطيع حجزه أو تأخيره. دورنا التأكيد والإشعار فقط.

كم يأخذ التأكيد؟

من دقيقة إلى ثلاث دقائق بعد وصول التحويل، لأننا ننتظر تثبيته على الشبكة.

ماذا لو أرسل العميل مبلغاً مختلفاً؟

المبلغ وصل إلى محفظتك فعلاً، لكن الفاتورة تبقى غير مدفوعة، وتسوّيه أنت مع عميلك.

ماذا لو دفع بعد انتهاء المهلة؟

يُقبل الدفع خلال 20 دقيقة إضافية، ثم تُغلق الفاتورة نهائياً.

كيف أسترجع مبلغاً لعميل؟

المبلغ في محفظتك، فأنت من يعيده إليه.

تسرّب مفتاحي، ماذا أفعل؟

أنشئ مفتاحاً جديداً من التطبيق، فيتوقف القديم فوراً.

تتحمل أنت الالتزام بقوانين بلدك في بيع السلع والخدمات وقبول العملات الرقمية.
