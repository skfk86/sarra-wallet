# صُرّة — محفظة USDT غير احتجازية

محفظة متعددة الشبكات (TRON وBNB Smart Chain وEthereum وPolygon): إنشاء أو استيراد، قفل برمز PIN، الرصيد والسجل، إرسال واستلام، تبديل، نقل بين الشبكات (LI.FI)، وسوق P2P على BNB Smart Chain فقط.

## التشغيل

```bash
npm install
npm run vendor          # ينسخ TronWeb ومكتبة QR إلى src/vendor
npx cap add android
npm run build:debug     # APK في android/app/build/outputs/apk/debug/
npm test                # اختبارات النواة (بدون إنترنت)
```

## بنية المشروع

```
src/
  index.html          هيكل الشاشات فقط (HTML) + سكربت المظهر المبكر
  css/app.css         كل الأنماط
  wallet-core.js      نواة المحفظة: المفاتيح، التشفير، التوقيع، الأرصدة، الإرسال، التبديل، الجسور
  logic/              منطق صافٍ بلا واجهة، يُختبر في Node مباشرة
    format.js         عرض الأرقام والمبالغ (بلا تقريب يخفي مبلغاً)
    indicators.js     المؤشرات الفنية وإشارة التحليل والاختبار التاريخي
    records.js        دمج الخزنة، ومتوسط التكلفة والربح/الخسارة
    registry.js       سجل الشبكات والعملات وأزواج التداول، والفحص الأخير قبل التوقيع
  app/NN-*.js         وحدات الواجهة بالترتيب (تنقل، قفل، رئيسية، سجل، إرسال، إشعارات، تداول، P2P…)
  app.js              مولَّد: scripts/build-app.mjs يجمع app/*.js في نطاق مغلق واحد (لا يُعدَّل يدوياً، وغير محفوظ في git)
```

- إضافة عملة: صف في `ASSETS` داخل `src/logic/registry.js` (الاسم، الشعار، معرّف CoinGecko، وزوج Binance إن كانت للتداول) + عقدها المُتحقق منه في `EVM_CHAINS` داخل `src/wallet-core.js`. شبكاتها تُستنتج تلقائياً.
- إضافة شبكة EVM (مثل Base أو Arbitrum): صف في `EVM_CHAINS` (المعرّف، RPC، المستكشف، التوكنات) + شعار في `NET_LOGO`. تظهر تلقائياً في الرئيسية والإرسال والاستلام. افحص بعدها التبديل والنقل (معرّف الشبكة في LI.FI) وسجل المعاملات (مصدر السجل لتلك الشبكة)، وماسح الإشعارات (`supabase/functions/push-watch`) يحتاج إضافتها في `CHAINS` أيضاً.
- إضافة شاشة: وحدة جديدة في `src/app/` برقم يحدد ترتيبها، ومنطقها الحسابي في `src/logic/` مع اختبار في `test/`.
- `npm run build` يولّد `src/app.js` ويتحقق من صياغته، ويُشغَّل تلقائياً مع `npm run vendor` وفي اختبارات الواجهة.
- `npm test` اختبارات النواة والمنطق، و`bash test/ui/run.sh` اختبارات الواجهة (Playwright).

## بوابة الدفع للتجار (API مدفوع)

بوابة غير احتجازية: التاجر يستلم USDT مباشرة على محفظته، والخادم يطابق التحويل بالفاتورة عبر «مبلغ فريد» ويبلّغ التاجر بإشعار موقّع. الربح من رصيد مدفوع مسبقاً يُخصم منه 0.5% عن كل فاتورة مدفوعة.

- `supabase/functions/pay/app.ts`: منطق الخادم كله (الـ API، إدارة التاجر بطلبات موقّعة، الماسح `/cron`)، واختباره التكاملي بقاعدة بيانات وهمية في `test/pay-app.test.ts`. `index.ts` يوصله بـ Deno فقط.
- `supabase/functions/_shared/pay.ts`: المنطق الصافي (مبالغ، مطابقة، توقيع الإشعار)، واختباراته في `test/pay-logic.test.ts`.
- `supabase/migrations/020_pay.sql`: الجداول، التسديد الذرّي `pay_settle`، والجدولة.
- `src/app/16-merchant.js`: شاشة التاجر في التطبيق. `docs/pay.html`: صفحة الدفع للعميل. `docs/api.html`: توثيق المطوّرين.
- النشر: Actions ← Deploy edge function ← `pay-setup`. يحتاج المتغيرين `SARRA_FEE_ADDRESS` (TRON) و`SARRA_EVM_FEE_ADDRESS` (0x) كعنواني شحن الرصيد.
- إعدادات اختيارية في أسرار الدوال: `PAY_FEE_BPS` (50)، `PAY_FEE_MIN_USDT` (0.02)، `PAY_PAGE_URL`.

## الإعدادات (src/config.js، يُكتب وقت البناء)

- الشبكة الافتراضية: **mainnet** (شبكة TRON الحقيقية). لبناء نسخة اختبار على Nile: Actions ← Build Android APK ← Run workflow ← network: nile.
- `TRONGRID_API_KEY` — مفتاح مجاني من trongrid.io لتجنّب حدود الطلبات.

للحصول على TRX وUSDT تجريبيين على Nile: صنبور الشبكة الرسمي nileex.io.
تحقق من عنوان عقد USDT على Nile في `wallet-core.js` من مستكشف nile.tronscan.org قبل الاختبار.

## الأمان

- كلمات الاسترجاع تُشفَّر بـ AES-256-GCM بمفتاح مشتق من رمز PIN عبر PBKDF2 (600 ألف تكرار).
- التخزين المشفّر في Preferences الخاصة بالتطبيق (نقل المفتاح إلى Android Keystore مخطط لاحقاً).
- المفتاح الخاص يبقى في الذاكرة فقط بعد فتح القفل، ويُمسح عند القفل.
- قفل تلقائي بعد دقيقة في الخلفية، وتأخير متصاعد بعد 5 محاولات خاطئة.
- لا يُرسل أي مفتاح أو كلمات لأي سيرفر.
